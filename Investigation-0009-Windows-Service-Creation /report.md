## Objective

Investigate the creation of a new Windows service using the **Service Control (sc.exe)** utility, verify how Windows processes the request, and correlate the resulting Registry modifications and System events.

---

## Summary

User **gamal** created a new Windows service named **SOC-Service** using the Windows **sc.exe** utility.

Sysmon captured the execution of **sc.exe**, revealing the complete command line used to create the service.

Further investigation showed that **services.exe** (Service Control Manager) processed the request by modifying the Windows Registry under the **Services** registry hive.

Finally, Windows generated **System Event ID 7045**, confirming that the new service was successfully installed.

No evidence of malicious behavior or unauthorized persistence was identified. The activity was part of a controlled laboratory exercise.

# Investigation

The investigation began after identifying the execution of **sc.exe** within Sysmon Process Creation events.

The captured command line showed that user **gamal** executed the following command to create a new Windows service named **SOC-Service**, configured to launch **notepad.exe**.

Although **sc.exe** initiated the request, additional investigation was required to determine whether Windows successfully created the service.

Searching Elastic for **SOC-Service** revealed Registry modification events generated by **services.exe**, the Windows **Service Control Manager**.

The Registry path:

```text
HKLM\System\CurrentControlSet\Services\SOC-Service
```

was created and configured, confirming that Windows accepted the request and stored the service configuration.

Finally, Windows System logs generated **Event ID 7045**, confirming that the operating system successfully installed the new service.

The event recorded:

- Service Name: **SOC-Service**
- Service File: **C:\Windows\System32\notepad.exe**
- Service Type: User Mode Service
- Start Type: Demand Start
- Service Account: LocalSystem

Correlating these events reconstructed the complete service creation lifecycle.

---

# Analysis

Windows service creation involves multiple components.

The investigation demonstrated the following execution chain:

```text
PowerShell
        │
        ▼
sc.exe
(Process Creation)
        │
        ▼
services.exe
(Registry Modification)
        │
        ▼
Windows System Log
(Event ID 7045)
```

The **sc.exe** utility does not directly modify the Registry.

Instead, it sends a request to the **Service Control Manager (services.exe)**, which performs the privileged Registry operations and registers the service within Windows.

This distinction is important during incident response because attackers frequently abuse **sc.exe** to establish persistence through malicious Windows services.

Correlating Sysmon events with Registry activity and System logs provides a complete understanding of the service creation process.
