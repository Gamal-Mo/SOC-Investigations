# Investigation Report — INV-0009

## Title

Registry Run Key Persistence Using `reg.exe`

---

## Date

2026-07-28

---

## Lab Environment

- **SIEM:** Elastic Security
- **Endpoint:** Windows 10 Pro
- **Host:** DESKTOP-0DFKSAT
- **Log Source:** Sysmon Operational
- **Provider:** Microsoft-Windows-Sysmon

---

## Objective

Investigate the creation of a Windows Registry Run Key using the native **reg.exe** utility, identify the process responsible for the Registry modification, and determine whether the persistence mechanism is malicious or benign.

---

## Summary

User **gamal** created a Registry Run Key named **SOC-Lab** using the Windows **reg.exe** utility from an elevated PowerShell session.

Sysmon recorded the execution of **reg.exe** (Event ID 1) and subsequently logged a **Registry Value Set** event (Event ID 13). Correlation using **process.entity_id** confirmed that the same **reg.exe** process modified the Registry.

The newly created Run Key was configured to execute **notepad.exe** whenever the user logs on.

No malicious behavior was identified. The activity was intentionally generated as part of a SOC investigation lab.

# Attack Simulation

The following command was executed from an elevated PowerShell session.

```cmd
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v SOC-Lab /t REG_SZ /d "notepad.exe"
```

### Command Explanation

| Argument | Description |
|----------|-------------|
| `reg` | Windows Registry command-line utility. |
| `add` | Creates a new Registry key or value. |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | Registry location used for user logon persistence. |
| `/v SOC-Lab` | Creates a Registry value named **SOC-Lab**. |
| `/t REG_SZ` | Specifies the Registry value type as a string. |
| `/d "notepad.exe"` | Specifies the data that will be executed when the user logs on. |

# Investigation

The investigation began by identifying the execution of **reg.exe** through **Sysmon Event ID 1**.

The process command line revealed that user **gamal** executed a command to create a new Registry value named **SOC-Lab** under the Windows **Run** Registry key.

The **process.entity_id** associated with the Process Create event was then used to pivot across all telemetry generated by the same process instance.

The pivot identified a corresponding **Sysmon Event ID 13 (Registry Value Set)** that shared the same **process.entity_id**, confirming that the Registry modification was performed by the same **reg.exe** process.

The Registry event recorded the following path:

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SOC-Lab
```

The Registry value was configured as:

```text
notepad.exe
```

Further analysis showed that **reg.exe** was launched by **powershell.exe**, establishing the following execution chain:

```text
powershell.exe
        │
        ▼
reg.exe
        │
        ▼
Registry Run Key Created
```

No additional Registry modifications or suspicious child processes were observed during the investigation.

---

# Analysis

Registry Run Keys are one of the most commonly abused persistence mechanisms on Windows systems.

Any executable configured under the **CurrentVersion\Run** Registry key is automatically executed when the associated user logs on.

Correlation between **Sysmon Event ID 1 (Process Creation)** and **Sysmon Event ID 13 (Registry Value Set)** using **process.entity_id** confirmed that **reg.exe** was directly responsible for modifying the Registry.

Although Registry Run Keys are frequently used by attackers to establish persistence, the configured executable (**notepad.exe**) was intentionally selected for this laboratory exercise and does not represent malicious activity.

# Lessons Learned

- Investigated Registry persistence using Sysmon telemetry.
- Correlated Process Create and Registry Value Set events using **process.entity_id**.
- Identified the parent-child relationship between **powershell.exe** and **reg.exe**.
- Verified the Registry path and value configured for automatic execution.
- Reinforced how Registry Run Keys are commonly abused to establish persistence.
- Practiced process correlation using **process.entity_id** to reconstruct the complete execution chain.
